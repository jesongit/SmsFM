# SmsFM 网页远控开发计划

- 更新日期：2026-10-24
- 状态：计划已确认，尚未开始实现
- 使用场景：局域网内 1–20 台手机，由一个管理员使用网页操作
- 参考项目：工作区内已克隆的 `SmsForwarder/`

## 1. 开发范围

建立独立的网页控制台，接入 SmsForwarder 已有的远控接口，并提供局域网扫描连接和手动连接。第一版复用现有 Android App，无需修改 APK。

网页只保留设备列表、当前设备操作区和连接设置。业务数据直接查询手机，控制台只保存连接参数及必要凭据。

接入以下九项已有能力：

| 能力 | 现有接口 |
| --- | --- |
| 查询短信 | `POST /sms/query` |
| 发送短信，选择 SIM | `POST /sms/send` |
| 查询通话记录 | `POST /call/query` |
| 查询联系人 | `POST /contact/query` |
| 添加联系人 | `POST /contact/add` |
| 查询电量及充电状态 | `POST /battery/query` |
| 查询定位缓存 | `POST /location/query` |
| WOL 唤醒 | `POST /wol/send` |
| 配置克隆、导出和恢复 | `POST /clone/pull`、`POST /clone/push` |

连接时调用 `POST /config/query` 读取设备信息、SIM 信息、版本和功能开关，并据此启用操作入口。

本计划不包含屏幕查看、点击操作或远程桌面，也不加入统一收件箱、Webhook、短信业务数据库、网页已读状态、分组权限、批量任务或额外管理看板。

## 2. 已完成的真实网络探测

探测环境：本机 IPv4 为 `192.168.1.2`，局域网为 `192.168.1.0/24`。排除本机后，对 253 个地址的默认 TCP `5000` 端口进行探测。

用户本轮启动了一台手机的远控服务，已通过只读配置接口确认：

| 项目 | 结果 |
| --- | --- |
| 地址 | `192.168.1.10:5000` |
| 设备名称 | 测试手机（入门安卓机） |
| App 版本 | `3.3.2.240815`，版本代码 `100053` |
| 配置查询 | HTTP 200，业务 `code=200` |
| 凭据情况 | 本次未携带密钥的配置请求成功；不能据此确定手机选择的安全模式 |
| 功能开关 | 定位关闭，其余八项远控功能开启 |

临时探测程序的实测耗时：

| 测试 | 参数和结果 |
| --- | --- |
| 快速扫描并完成配置识别，重复三轮 | 128 并发、350ms TCP 连接超时；全流程分别为 763ms、743ms、741ms，每轮识别一台设备 |
| 首台设备完成配置识别 | 三轮分别为 589ms、231ms、272ms |
| 手动地址直连配置接口 | 三轮分别为 494ms、20ms、19ms |
| 较长超时全网段复查 | 64 并发、1000ms TCP 连接超时；约 4.04 秒，发现同一台设备 |

这些数据来自临时探测程序，不是待开发 Go 后端的性能验收结果。重复探测可能受邻居缓存和设备唤醒状态影响，不能推广为所有网络下的固定耗时。

当前仅验证了一台手机的发现和配置查询。第二台手机同时发现、各业务接口、其他鉴权模式、双卡发送及息屏稳定性尚未完成真机验收。功能开关开启也不代表 Android 权限、SIM 或业务操作已验证可用。

## 3. 扫描与连接方案

### 3.1 局域网扫描

采用“并发快扫、发现即展示、后台复查”的流程：

1. 后端识别实际联网网卡及其 IPv4 网段，允许选择扫描网段和端口。默认端口为 `5000`，扫描范围以界面显示的范围为准。
2. 已保存地址和邻居缓存中的地址优先探测，但不以它们作为完整设备清单。
3. 对选定网段进行 TCP 快速扫描，初始参数采用本次验证过的 128 并发、350ms 连接超时。
4. 发现开放端口后，立即调用只读 `/config/query` 并检查响应结构。配置识别与剩余地址扫描并行进行，识别成功即展示设备。
5. 对快速扫描超时的地址进行一次后台复查，初始参数采用 64 并发、1000ms 连接超时。复查不阻止用户选择已发现的设备。
6. 展示扫描范围、进度、发现结果和复查状态，允许取消扫描。

不把 Ping 成功作为扫描前提。端口开放仅表示候选服务，不能直接标记为 SmsForwarder。

无凭据请求返回明确签名错误时，标记为待配置凭据的候选；其他非 JSON 或加密响应保留为未验证候选，不能仅凭密文形状判断产品或安全模式。填写正确安全模式及凭据后，再通过配置查询验证。

扫描由后端执行，发现范围是后端所在或可达的局域网，而不是浏览器所在的网络。默认快速扫描不穷举全部端口；手机使用自定义端口时，可指定该端口扫描或使用手动连接。

### 3.2 手动连接与保存连接

- 输入手机 IP、端口、安全模式及必要密钥，调用配置接口进行连接测试。
- 兼容现有的无安全措施、签名、RSA 和 SM4 模式。
- 支持保存连接、切换设备、编辑地址和凭据、删除保存的连接。
- 分别展示连接失败、鉴权失败、功能关闭和业务错误。
- 连接条目使用控制台内部标识；IP 和设备备注均可变化，不凭备注自动合并设备。地址变化后重新扫描或手动更新连接。

### 3.3 性能验收目标

在与本次一致的 `/24` 网段、设备远控服务正常且网络可达的场景下，快速扫描并完成配置识别的目标为 **2 秒以内**。实现后使用真实 Go 后端重新测试。

后台复查单独显示进度和耗时，不要求首批结果等待复查结束。350ms 可能漏掉 Wi-Fi 响应较慢的设备，因此保留复查和手动连接；不承诺在所有网络条件下固定耗时或绝不漏检。

## 4. 技术与交互安排

- 前端：Vue 3 + TypeScript。
- 后端：Go，负责设备扫描、连接保存、现有协议适配和手机接口调用。
- 数据：本地保存必要的连接设置；短信、通话和联系人直接查询手机，不建立额外业务数据库。
- 页面：设备列表、当前设备操作区、连接设置。
- 设备操作入口按手机返回的功能开关启用；发送界面明确显示当前设备和 SIM。

## 5. 分阶段开发计划

| 阶段 | 开发内容 | 验收标准 |
| --- | --- | --- |
| 1. 项目与协议适配 | 建立前后端项目；封装现有请求、响应、签名、RSA、SM4 和错误处理；保存连接配置 | 兼容本次手机版本；同时检查 HTTP 状态与业务 code；正确区分连接、鉴权、功能开关和业务错误 |
| 2. 扫描与手动连接 | 实现并发快扫、配置识别、后台复查、进度和取消；实现手动连接及连接管理 | 两台手机同时发现；自定义端口手动连接成功；在约定场景达到扫描耗时目标 |
| 3. 接入已有功能 | 接入九项远控能力；适配 SIM 参数、查询及结果展示；根据配置开关启用入口 | 请求及结果语义与原客户端一致；设备和 SIM 选择明确；关闭功能有明确说明 |
| 4. 真机联调与交付 | 验证双设备切换、鉴权、息屏、断网、地址变化和配置恢复；完成运行包与使用说明 | 两台真机完成接入及业务验收；核对性能、故障状态和写操作结果表达 |

依赖顺序为：协议适配 → 扫描与连接 → 已有功能接入 → 真机验收与交付。配置恢复等影响手机现有数据的操作安排在独立测试步骤中。

## 6. 必须保留的协议语义

- HTTP 200 不一定代表操作成功，还需检查响应中的业务 `code`。
- 短信发送接口成功不代表对方已经收到；超时显示结果未知，不自动重发。
- 配置中的 SIM 索引与发送接口参数需转换；无法确认 SIM 时阻止提交，实际行为需双卡真机验证。
- 定位接口读取缓存，显示定位时间；不声称主动触发了新定位。
- WOL 接口成功不代表目标电脑已经开机。
- 查询空列表可能与权限或查询异常有关，不把它一概解释为手机没有记录。
- 联系人查询的实际分页行为需由适配层核对，避免直接假定手机严格按页返回。
- 配置恢复沿用上游语义，可能替换设置并清理部分数据，操作页需明确展示影响范围。
- 安全模式按上游协议兼容，不把现有时间戳签名描述为完整的防篡改或防重放机制。

## 7. 验证边界

模拟测试用于验证协议格式、错误分类、扫描并发与取消等程序行为；真实设备验收用于验证局域网发现、鉴权互通、系统权限、双卡发送、息屏和地址变化。两类结果分别记录。

当前阶段仅保存开发计划。尚未创建网页项目或实现任何功能，SmsForwarder 克隆源码保持原样。
